# Harness Phase 1.5 — Run Metadata Off Git (the deferred Task 7)

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tests run with **base python** (`python -m pytest <path> -v`) — the `evolve` conda env has no pytest, but the pure-python `harness/` modules import fine in base.

**Goal:** Move run metadata (`state` / `portfolio` / `decisions` / `candidate_meta` / `HISTORY`) out of git so git commits become **code checkpoints only**, killing the per-iter metadata-commit churn — *without* weakening the candidate scope-violation guard or the rollback that today depend on `runs/_summary/` being git-tracked.

**Architecture:** Today `runs/*` is tracked except `runs/_summary/`, and `commit_iteration` git-adds `transcribe.py` + `HISTORY.md` + decisions/meta/state on **every** iter; the scope guard (`disallowed_*_paths`) and `rollback_paths` are built on `git status --porcelain --untracked-files=all` (which ignores ignored paths) + `git restore` + `git clean -fd` (no `-x`). This plan blanket-ignores `runs/`, makes the scope guard read `git status --porcelain -uall --ignored` (which **does** report ignored files per-path when `-uall` is set — verified below) so candidate writes into an ignored `runs/_summary/` are still caught, replaces the `git clean -fd` rollback with a **precise filesystem delete** of exactly the offending paths (no collateral damage to unrelated untracked files), and gates `commit_iteration` so only code-advancing statuses commit. The F2 abort-commit becomes obsolete (state is durable-on-disk + untracked, so `ensure_worktree_ready` never sees it as a modified tracked file) and is removed.

**Tech Stack:** Python 3.12 (base interpreter for tests; `evolve` conda env for live runs), pytest 9, git (cli via `subprocess`), existing `harness/` package. Standard-lib only (`os`, `shutil`, `subprocess`) — no new deps.

## Why this was deferred (the collision) and how this plan resolves it

The Phase 1 plan's **Task 7 banner** records the blocker exactly: fully gitignoring `runs/` silently disables two production safety mechanisms.

1. **Scope-violation detection.** `git_status` (`runner.py:292`) calls `git status --porcelain --untracked-files=all`, which does **not** report *ignored* paths. With `runs/` ignored, a candidate writing into `runs/_summary/<job>_state.json` / `baseline/` / `docs/` during `transcribe` (the verify-time arbitrary-I/O surface — `disallowed_post_verify_paths`, `runner.py:318`) is no longer caught. This is a real security regression, not a test artifact.

2. **Rollback.** `rollback_paths` (`runner.py:356`) uses `git restore` (cannot restore an untracked/ignored file) + `git clean -fd` **without `-x`** (will not remove ignored files). Poison under an ignored `runs/` cannot be rolled back.

3. **F2 abort-commit.** `run_job` commits aborted state via `commit_iteration(..., "abort", ...)` (`runner.py:2315/2335/2359/2373`). A status-gated commit-code-only rule makes that a no-op, breaking `test_run_job_commits_aborted_state_when_commit_results` (`tests/test_harness_runner.py:1071`).

**Real-world hazard (from the task brief, and from the lost prior copy of this very plan):** while a job was running, an untracked file created *elsewhere* in the repo was silently deleted by `git clean -fd` on a reject iter, because `candidate_owned_statuses` (`runner.py:367`) treats **every** untracked path outside `runs/<hyp_id>/` as candidate junk:

```python
def candidate_owned_statuses(statuses, config):
    return [
        status for status in statuses
        if status.path == config.allowed_path
        or status.path.parts[:2] == ("runs", "_summary")
        or status.path.parts[:1] != ("runs",)          # ← ANY non-runs untracked path
    ]
```

That third clause is the bug: a stray untracked file the candidate never touched (e.g. an operator's scratch file) matches `parts[:1] != ("runs",)` and gets `git clean -fd`'d. The new guard/rollback in this plan **only deletes paths the candidate actually created/modified this iteration** (diffed against a pre-candidate baseline), eliminating the collateral-damage clause entirely.

### Empirical verification of the git behaviors this plan relies on

Run in a scratch repo with `.gitignore` = `runs/`:

```
$ git status --porcelain --untracked-files=all        # current guard — BLIND to ignored
                                                       # (empty: poison under runs/ invisible)
$ git status --porcelain -uall --ignored              # NEW guard — per-path, sees ignored
?? stray.txt                                           # untracked, non-ignored (outside runs/)
!! runs/_summary/poison.txt                            # ignored file (candidate poison)
!! runs/h1/out.json                                    # ignored file (legit verify output)
```

Two facts this plan depends on, both confirmed:
- `--ignored` **without** `-uall` collapses to a directory line (`!! runs/`); `--ignored` **with** `-uall` lists ignored files **per path** (`!! runs/_summary/poison.txt`). We always pass `-uall`.
- `git clean -fdx -- runs/_summary` removes the **whole** dir (our own metadata too) — too blunt. Precise `os.remove(path)` / `shutil.rmtree(path)` of exactly the offending paths is both sufficient and collateral-free.

## Design decisions (required by the spec — each justified)

### D1 — Scope-violation guard without git tracking of `runs/`: **(c) hybrid, git-status-based**

Three options were on the table:
- **(a) Filesystem snapshot diff** — walk the repo before the candidate runs (pruning `.git/`, `data/`, caches, the current `runs/<hyp_id>/`), record `{path: mtime/size/hash}`, walk again after, diff. *Rejected as the primary mechanism:* it re-implements what git already knows (ignore rules, tracked vs untracked), is O(repo) on every iter (the repo has large tracked trees), and needs its own prune list that will drift from `.gitignore`. It also can't cheaply tell "tracked-but-modified" from "untracked-new" the way git does.
- **(b) `git status --ignored` + scoped `git clean -fdx`** — *rejected for the delete half:* `git clean -fdx -- runs/_summary` is directory-blunt (verified above) and would wipe our own durable metadata; and `git clean` is exactly the tool that caused the real-world collateral-damage hazard.
- **(c) hybrid — chosen.** Keep git as the **source of truth for detection** (it already encodes ignore rules and tracked state), but switch the status query to `git status --porcelain -uall --ignored` so ignored files appear **per-path**; classify each path by its two-char code (`??` = untracked non-ignored, `!!` = ignored, ` M`/`MM`/… = tracked-modified); and do the **removal in Python** (`os.remove` / `shutil.rmtree`) on exactly the offending paths, never `git clean`.

Detection logic (unchanged in spirit — same allow-list): a path is allowed iff it is `config.allowed_path` (`workspace/transcribe.py`, git-tracked, unaffected) **or** under `runs/<hyp_id>/` (the candidate's own verify-output dir). Everything else — including any write into `runs/_summary/`, `baseline/`, `docs/`, or a new top-level file — is a violation. This is the **same allow-list the code already enforces** in `disallowed_post_verify_paths`; we are only changing *where the candidate's writes become visible* (now also ignored paths) and *how violations are reverted* (precise fs delete). The **post-verify** check (`transcribe` does arbitrary I/O during verify) stays the security-critical one and stays **before** baseline/noise reads (`runner.py:2068-2095`), unchanged in ordering.

### D2 — Rollback of an ignored/untracked tree, without nuking unrelated untracked files

Replace the `git clean -fd` half of `rollback_paths` with a precise remover that takes the **already-classified candidate-owned status list** and deletes each path with the right tool:
- tracked-modified (`code[1] != ' '` or `code` is e.g. ` M`/`MM`/`A `) → `git restore -- <path>` (restores to HEAD; works because the file is tracked — `workspace/transcribe.py` is the only such path).
- untracked/ignored (`??` / `!!`) → `os.remove(path)` if file, `shutil.rmtree(path)` if dir. **Only paths in the passed list** — which now comes from the precise `candidate_owned_statuses` (D1, fixed in Task 2) — so an unrelated stray untracked file is never in the list and never deleted.

`workspace/transcribe.py` itself is **git-tracked and unaffected** by the `runs/` ignore, so its rollback (`git restore`) is exactly as before. Champion rollback on set `reset` already uses `gitops.restore_file_from_ref` (`runner.py:2118/2254`) — also unaffected (it restores a tracked file from a ref).

### D3 — `commit_iteration` code-only + `.gitignore` → `runs/` + remove F2 abort-commit

- `.gitignore` `runs/*` + `!runs/_summary/` → blanket `runs/`. Metadata files stay durable-on-disk via the **existing atomic writes**: `HarnessState.save` (`state.py:63-71`, tmp + `os.replace`), `Portfolio.save` (`portfolio.py:242-247`, tmp + `os.replace`), and the jsonl/`HISTORY.md` **appends** (`_persist_decision`/`_persist_candidate_meta`/`history.append_event`). resume reads files only (`load_or_init_state`, `runner.py:1864`) — no git needed.
- `commit_iteration` (`runner.py:1826`) stops staging metadata. It still calls `_persist_candidate_meta`/`_persist_decision` (they write the durable files), then commits **only** `config.allowed_path`, and **only** for code-advancing statuses (`keep`, `success`, `lineage_advance`). `reject`/`abort` become no-ops (nothing to commit — the tree is clean because `runs/` is ignored and the workspace was already rolled back).
- **F2 abort-commit is now obsolete.** Its sole purpose (per the `runner.py:2352-2357` comment) was so the next job's `ensure_worktree_ready` wouldn't see `runs/_summary/<job>_state.json` as a *modified tracked file* and refuse to start. Once `runs/` is ignored, the state file is **never a tracked file**, so a dirty state file can never trip `ensure_worktree_ready` (which checks `disallowed_candidate_paths` + workspace-dirty, both now blind to ignored `runs/`). The four `commit_iteration(..., "abort", ...)` calls in `run_job` (`runner.py:2315/2335/2359/2373`) become guaranteed no-ops (status not in the code-advancing set) — we remove them and update `test_run_job_commits_aborted_state_when_commit_results`.

### D4 — Interaction with the Phase 1 lineage-set (`--set-budget>1`)

The set path (already implemented, `runner.py:2214-2280`) calls `commit_iteration` with `lineage_advance` / `keep` / `success` / `reject` and, on `promote`, reads `git rev-parse HEAD` then `gitops.advance_champion_ref(repo, ref, HEAD)`.
- **Code-only commits still give a real HEAD for champion advance.** `lineage_advance` / `keep` / `success` are in the code-advancing set, so they commit `workspace/transcribe.py` → HEAD moves to a real commit containing the promoted code → `advance_champion_ref(HEAD)` is correct. (If the promoted code is byte-identical to the prior lineage commit, `commit_iteration` skips — `git diff --cached --quiet` returns 0 — and `rev-parse HEAD` returns the existing lineage commit, which still contains the code; champion advance is still correct.)
- **Metadata-only iters (reject = repair/reset) simply don't commit.** With code-only staging, a `reject` stages nothing (workspace already rolled back to lineage/champion → no diff) and commits nothing; the tree stays clean because `runs/` is ignored. This **eliminates the Phase-1 "accepted churn"**: the reset-restore-to-champion previously produced a noisy revert commit (Phase 1 plan Task 8 "accepted churn" caveat) — now `restore_file_from_ref` leaves the tree clean (file == HEAD's lineage code... or != if reset restored champion; see note) and the `reject` commit is skipped.
  - **Subtlety to cover in tests:** on `reset`, `restore_file_from_ref(champion)` may leave `workspace/transcribe.py` *differing from the job-branch HEAD* (which is the lineage head, not champion). That is an **untracked-content difference on a tracked file** → it shows as ` M workspace/transcribe.py`, a *tracked-modified* path, NOT an ignored one. The next iter's `ensure_worktree_ready` would reject it as "workspace dirty before candidate generation". **Therefore reset must still commit the champion-restore as a code checkpoint** so HEAD == champion code and the tree is clean. Decision: keep a commit on `reset` *only* — i.e. treat `reset` as a code-advancing checkpoint. We implement this by committing the workspace on `reset` too (see Task 4, Step 3 — `reset` joins the code-advancing set, `repair` does not). This is correct and minimal: `reset` genuinely changes the on-disk code (back to champion), so it *is* a code checkpoint; `repair` rolls back to the lineage head == current HEAD, so its tree is already clean and no commit is needed.

### D5 — `_init_repo` and the scope-violation tests updated to the new guard

`_init_repo` (`tests/test_harness_runner.py:58`) writes `.gitignore` = `runs/*\n!runs/_summary/\n` and `git add`s `runs/_summary/HISTORY.md`. Update the `.gitignore` to `runs/\n` (match production) and **drop** the `runs/_summary/HISTORY.md` from the initial `git add` (it is now ignored; `git add` of an ignored path errors). The two scope-violation tests (`test_run_iteration_rejects_and_rolls_back_summary_scope_violation`, `test_run_iteration_rejects_when_candidate_writes_summary_during_verify`) keep their *assertions* (poison removed, original restored, reject narrative appended) — they pass against the new guard because the new guard sees ignored-path writes. `test_step1_decision_trace_committed_and_survives_next_iter` converts its `_tracked(...)` asserts to on-disk-existence asserts (the trace is durable-but-untracked).

def git_status(repo_root: Path) -> list[GitPathStatus]:
    # -uall lists individual untracked files (not just dirs); --ignored adds
    # ignored files with code "!!" — REQUIRED for the scope guard once runs/ is
    # gitignored (phase1.5), so candidate writes into the ignored runs/_summary/

    statuses: list[GitPathStatus] = []
    for line in result.stdout.splitlines():
        if not line:
            continue
        code = line[:2]
        raw_path = line[3:]
        if " -> " in raw_path:
            raw_path = raw_path.split(" -> ", 1)[1]
        statuses.append(GitPathStatus(code=code, path=Path(raw_path)))
    return statuses

```python
def candidate_owned_statuses(
    statuses: list[GitPathStatus], config: RunnerConfig
) -> list[GitPathStatus]:
    """Paths the candidate is responsible for and that rollback may revert.

    PRECISE (phase1.5): exactly the candidate's own surface —
      - config.allowed_path (workspace/transcribe.py),
      - anything under runs/<job_id>_iter_NNN/ (own verify output),
      - anything under runs/_summary/ (poison the candidate wrote there).
    Crucially this NO LONGER returns arbitrary non-runs/ untracked paths: a stray
    untracked file the candidate never created must never be deleted by rollback
    (the real-world git-clean collateral-damage hazard). A write outside this set
    is a scope VIOLATION — detected by disallowed_*_paths and rejected — but it is
    not 'owned', so rollback won't touch unrelated files. The violating poison is
    itself removed because a candidate violation only ever writes inside the repo
    surfaces we DO own (runs/_summary/, runs/<hyp>/) or to a tracked path
    (restored via git); a brand-new top-level file written by the candidate is
    still owned via the runs/_summary/ + allowed_path rule's complement below.
    """
    owned: list[GitPathStatus] = []
    for status in statuses:
        parts = status.path.parts
        if status.path == config.allowed_path:
            owned.append(status)
        elif parts[:2] == ("runs", "_summary"):
            owned.append(status)
        elif parts[:1] == ("runs",):
            # runs/<hyp_id>/... — the candidate's own per-iter output dir.
            owned.append(status)
    return owned
```

> **Design note (why this is still safe):** the previous third clause `parts[:1] != ("runs",)` existed to *clean up candidate writes to new top-level paths* (e.g. the candidate creates `docs/foo`). Those are caught as **scope violations** by `disallowed_*_paths` (which reject the iter) — but with the old clause they were also *deleted* as "owned", which is what swept up the unrelated stray file. The precise version owns only the candidate's three legitimate surfaces. A candidate write to a *new* path outside those (e.g. `docs/foo`) is still **detected and the iter rejected**; the poison file is left on disk untracked-but-present. To preserve "poison is removed" for that case without re-introducing the collateral hazard, the **scope-violation reject path removes exactly the detected violation paths** (the `disallowed`/`post_violations` lists), see Task 4 Step 2 — those lists are precisely the paths the candidate wrote outside its surface, so deleting them is collateral-free. Thus: candidate-owned rollback (this fn) handles the *legitimate* surfaces; violation-path removal handles the *illegitimate* writes; neither touches an unrelated stray file.

```python
def rollback_paths(repo_root: Path, statuses: list[GitPathStatus]) -> None:
    """Revert exactly the given paths. Tracked-modified → git restore (back to
    HEAD). Untracked/ignored → precise filesystem delete (os.remove / rmtree) of
    ONLY the listed paths — never `git clean`, which (a) won't remove ignored
    files and (b) caused the real-world collateral deletion of an unrelated
    untracked file (phase1.5). Callers pass candidate_owned_statuses(...) or the
    precise scope-violation list, so nothing outside the candidate's writes is
    ever passed here."""
    if not statuses:
        return
    tracked = [
        str(s.path) for s in statuses if not (s.untracked or s.ignored)
    ]
    removable = [s for s in statuses if s.untracked or s.ignored]
    if tracked:
        _run_git(repo_root, ["restore", "--", *tracked])
    for s in removable:
        target = repo_root / s.path
        if target.is_dir() and not target.is_symlink():
            shutil.rmtree(target, ignore_errors=True)
        elif target.exists() or target.is_symlink():
            try:
                target.unlink()
            except FileNotFoundError:
                pass
```
