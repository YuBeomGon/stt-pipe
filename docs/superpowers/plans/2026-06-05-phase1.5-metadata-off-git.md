# Harness Phase 1.5 — Run Metadata Off Git (the deferred Task 7)

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tests run with **base python** (`python -m pytest <path> -v`) — the `evolve` conda env has no pytest, but the pure-python `harness/` modules import fine in base.

**Goal:** Move run metadata (`state` / `portfolio` / `decisions` / `candidate_meta` / `HISTORY`) out of git so git commits become **code checkpoints only**, killing the per-iter metadata-commit churn — *without* weakening the candidate scope-violation guard or the rollback that today depend on `runs/_summary/` being git-tracked.

**Architecture:** Today `runs/*` is tracked except `runs/_summary/`, and `commit_iteration` git-adds `transcribe.py` + `HISTORY.md` + decisions/meta/state on **every** iter; the scope guard (`disallowed_*_paths`) and `rollback_paths` are built on `git status --porcelain --untracked-files=all` (which is blind to ignored paths) + `git restore` + `git clean -fd` (no `-x`). This plan blanket-ignores `runs/`. Once `runs/` is ignored, git can no longer see candidate writes into `runs/_summary/` at all, so detection of *that* surface moves to a **pre/post filesystem snapshot diff** of exactly the watched ignored surface (`runs/_summary/` files + the top-level `runs/<dir>` listing) — NOT a full-tree scan and NOT `git status --ignored`. The **tracked** surface (writes to `baseline/`, `docs/`, any tracked path) is still caught by the unchanged `git status --porcelain --untracked-files=all` query. Rollback of the diff-flagged ignored poison is a **precise filesystem delete** (`os.remove`/`shutil.rmtree`) of exactly the offending paths (no collateral damage to unrelated untracked files); tracked-path rollback stays `git restore`. `commit_iteration` is gated so only code-advancing statuses commit. The F2 abort-commit becomes obsolete (state is durable-on-disk + untracked, so `ensure_worktree_ready` never sees it as a modified tracked file) and is removed.

**Tech Stack:** Python 3.12 (base interpreter for tests; `evolve` conda env for live runs), pytest 9, git (cli via `subprocess`), existing `harness/` package. Standard-lib only (`os`, `shutil`, `subprocess`) — no new deps.

## Revision note (2026-06-05)

A controller meta-review reworked the **detection design** of an earlier draft. The earlier draft proposed switching the scope guard to `git status --porcelain -uall --ignored` so candidate writes into the (newly) ignored `runs/` would still surface per-path, then feeding that into the existing allow-list (`disallowed_*_paths`). **That approach is broken at scale**: once `runs/` is blanket-ignored, `git status -uall --ignored` lists *every* pre-existing ignored file under `runs/` — empirically **2584 files** in this repo (all of `runs/_archive/` ≈ 263 archived jobs + `runs/_summary/` + every prior `runs/<hyp>/`). The allow-list (only `allowed_path` + `runs/<current_hyp>/`) would then flag all ~2584 as scope violations **every iteration** → a guaranteed false reject every iter → the harness fully bricked. The earlier draft's empirical block looked clean only because it ran in a fresh temp repo with no history. This rewrite therefore detects the ignored surface with a **pre/post snapshot diff** of just `runs/_summary/` + the `runs/` top-level dir listing (tiny, O(metadata) not O(repo)), which is immune to the 2584 pre-existing files (they are byte-identical in both snapshots) and also fixes the symmetrical false-positive where a pre-existing stray untracked file was wrongly rejected (review C1). The tracked surface keeps using plain `git status` (no `--ignored`). Everything else (`.gitignore` flip, code-only commits, F2-abort removal, the collateral-damage `candidate_owned_statuses` fix) is unchanged from the sound parts of the prior draft.

## Why this was deferred (the collision) and how this plan resolves it

The Phase 1 plan's **Task 7 banner** records the blocker exactly: fully gitignoring `runs/` silently disables two production safety mechanisms.

1. **Scope-violation detection.** `git_status` (`runner.py:292`) calls `git status --porcelain --untracked-files=all`, which does **not** report *ignored* paths. With `runs/` ignored, a candidate writing into `runs/_summary/<job>_state.json` during `transcribe` (the verify-time arbitrary-I/O surface — `disallowed_post_verify_paths`, `runner.py:318`) is no longer visible to git at all. This is a real security regression, not a test artifact. (Writes to *tracked* paths like `baseline/` / `docs/` are unaffected — they still show as `M`/`??` in plain `git status`. Only the now-ignored `runs/` surface loses git visibility.)

2. **Rollback.** `rollback_paths` (`runner.py:356`) uses `git restore` (cannot restore an untracked/ignored file) + `git clean -fd` **without `-x`** (will not remove ignored files). Poison under an ignored `runs/` cannot be rolled back by `git clean`.

3. **F2 abort-commit.** `run_job` commits aborted state via `commit_iteration(..., "abort", ...)` (`runner.py:2316/2336/2359/2373`). A status-gated commit-code-only rule makes that a no-op, breaking `test_run_job_commits_aborted_state_when_commit_results` (`tests/test_harness_runner.py:1071`).

**Real-world hazard (from the task brief, and from the lost prior copy of this very plan):** while a job was running, an untracked file created *elsewhere* in the repo was silently deleted by `git clean -fd` on a reject iter, because `candidate_owned_statuses` (`runner.py:367`) treats **every** untracked path outside `runs/<hyp_id>/` as candidate junk:

```python
def candidate_owned_statuses(statuses, config):
    return [
        status for status in statuses
        if status.path == config.allowed_path
        or status.path.parts[:2] == ("runs", "_summary")
        or status.path.parts[:1] != ("runs",)          # ← ANY non-runs untracked path
    ]
```

That third clause is the bug: a stray untracked file the candidate never touched (e.g. an operator's scratch file) matches `parts[:1] != ("runs",)` and gets `git clean -fd`'d. The new guard/rollback in this plan **only deletes paths the candidate actually created/modified this iteration** — for the tracked surface, exactly the `disallowed_*_paths` set; for the ignored surface, exactly the snapshot-diff set — eliminating the collateral-damage clause entirely. This is the same defect, in its larger form, as the 2584-file false-reject described in the Revision note: judging against the whole tree instead of a per-iter diff.

### Why the snapshot diff, not `git status --ignored` (the detection-design decision)

The obvious-looking fix — make the guard read `git status --porcelain -uall --ignored` so ignored writes surface per-path, then reuse the existing allow-list — **does not scale**. Empirically, in this repo:

```
$ git status --porcelain --untracked-files=all          # current guard (tracked surface)
?? stray.txt                                             # untracked, non-ignored — VISIBLE
                                                         # (nothing under ignored runs/ shown)

$ git status --porcelain -uall --ignored | wc -l        # the rejected approach
2584                                                     # ← every pre-existing ignored file
                                                         #   under runs/ (_archive/, _summary/,
                                                         #   every prior runs/<hyp>/)
```

Feeding those 2584 lines into the allow-list (`allowed_path` + `runs/<current_hyp>/`) flags all 2584 as violations every iteration. So the ignored surface is detected differently:

- **Pre-candidate snapshot** (right after `ensure_worktree_ready`): the set of `(relpath, mtime_ns, size)` for files under `runs/_summary/`, plus the set of existing top-level `runs/<dir>` names.
- **Post-verify re-snapshot**, then **diff**: any file under `runs/_summary/` that is new or whose `(mtime_ns, size)` changed, or any new top-level `runs/<dir>` that is not the current `runs/<hyp_id>/`, is candidate poison.

The 2584 pre-existing files are identical in both snapshots → never flagged. A pre-existing operator scratch file (anywhere) is in the *pre*-snapshot → never "new" → never flagged (fixes review C1). The diff is two cheap directory stats (`runs/_summary/` holds ~5 files/job), **not** an O(repo) walk, and **not** a re-implementation of git's ignore rules: git still owns *tracked*-surface detection; the snapshot only watches the two ignored sub-surfaces the candidate could poison.

> **Note on `git clean -fdx`:** even scoped, `git clean -fdx -- runs/_summary` removes the **whole** dir (our own durable metadata too) — too blunt, and `git clean` is exactly the tool that caused the real-world collateral-damage hazard. Precise `os.remove(path)` / `shutil.rmtree(path)` of exactly the diff-flagged paths is both sufficient and collateral-free.

## Design decisions (required by the spec — each justified)

### D1 — Scope-violation guard without git tracking of `runs/`: **pre/post snapshot diff for the ignored surface + unchanged git status for the tracked surface**

Detection is split by surface, because after the `.gitignore` flip the two surfaces have different visibility:

- **Tracked surface (unchanged).** `git_status` keeps `git status --porcelain --untracked-files=all` (NO `--ignored`). Writes to `baseline/`, `docs/`, any tracked path, or a new top-level untracked file still appear as `M`/`??` and are caught by `disallowed_candidate_paths` (pre-verify) and `disallowed_post_verify_paths` (post-verify) exactly as today. We do **not** add `--ignored` globally — doing so would surface all ~2584 pre-existing ignored files and brick the allow-list (Revision note).
- **Ignored surface (new).** The candidate's only legitimate ignored write target is `runs/<hyp_id>/` (its own verify-output dir). Any write into `runs/_summary/` (metadata poison) or any *other* new top-level `runs/<dir>` is a violation that git can no longer see. We catch it with a **pre/post filesystem snapshot diff** of just those two sub-surfaces (helpers `snapshot_ignored_surface` / `diff_ignored_surface`, Task 2).

Three alternatives were considered and rejected:

- **`git status -uall --ignored` + existing allow-list** — *rejected (the whole point of the Revision note):* lists all 2584 pre-existing ignored files → every iter is a false reject → harness bricked. It also can't distinguish "candidate wrote this *this iter*" from "this file existed before".
- **`git status --ignored` + scoped `git clean -fdx`** — *rejected for the delete half:* `git clean -fdx -- runs/_summary` is directory-blunt and would wipe our own durable metadata; and `git clean` caused the real-world collateral-damage hazard.
- **Full-tree filesystem snapshot** (walk the whole repo before/after, diff every path) — *rejected:* O(repo) on every iter (the repo has large tracked trees + 2584 ignored files), needs its own prune list that drifts from `.gitignore`, and re-implements what git already knows for the *tracked* surface. The chosen design walks **only** `runs/_summary/` + the `runs/` top-level dir listing (tiny) and leaves the tracked surface to git.

Detection logic is unchanged *in spirit* — same allow-list: a path is allowed iff it is `config.allowed_path` (`workspace/transcribe.py`, git-tracked, unaffected) **or** under `runs/<hyp_id>/` (the candidate's own verify-output dir). Everything else is a violation; we only changed *how* the now-ignored part of "everything else" becomes visible (snapshot diff) and *how* violations are reverted (precise fs delete). The **post-verify** check (`transcribe` does arbitrary I/O during verify) stays the security-critical one and stays **before** baseline/noise reads (`runner.py:2097-2098`), unchanged in ordering. (The harness itself does not write into `runs/_summary/` between the pre-snapshot and the post-verify diff point — `append_event`/`commit_iteration`/`state.save`/`_persist_*` all run *after* the post-verify check in every terminal branch — so any `runs/_summary/` change at the diff point is necessarily candidate poison.)

### D2 — Rollback of an ignored/untracked tree, without nuking unrelated untracked files

Replace the `git clean -fd` half of `rollback_paths` with a precise remover that takes a list of statuses and deletes each with the right tool:
- tracked-modified (`code` is e.g. ` M`/`MM`/`A `, not `??`) → `git restore -- <path>` (restores to HEAD; works because the file is tracked — `workspace/transcribe.py` is the only such path the candidate touches).
- untracked (`??`) → `os.remove(path)` if file, `shutil.rmtree(path)` if dir. **Only paths in the passed list.**

The ignored-surface poison is *not* passed to `rollback_paths` as `GitPathStatus` (git can't see it); instead the snapshot diff returns plain repo-relative `Path`s, removed by a sibling helper `remove_ignored_poison(repo_root, paths)` (Task 2) that does the same precise `os.remove`/`shutil.rmtree`. Net: tracked rollback via git, untracked/ignored rollback via precise filesystem delete, **never** `git clean` — so an unrelated stray untracked file is never deleted.

`workspace/transcribe.py` itself is **git-tracked and unaffected** by the `runs/` ignore, so its rollback (`git restore`) is exactly as before. Champion rollback on set `reset` already uses `gitops.restore_file_from_ref` (`runner.py:2118/2254`) — also unaffected (it restores a tracked file from a ref).

### D3 — `commit_iteration` code-only + `.gitignore` → `runs/` + remove F2 abort-commit

- `.gitignore` `runs/*` + `!runs/_summary/` → blanket `runs/`. Metadata files stay durable-on-disk via the **existing atomic writes**: `HarnessState.save` (`state.py:63-71`, tmp + `os.replace`), `Portfolio.save` (`portfolio.py:242-247`, tmp + `os.replace`), and the jsonl/`HISTORY.md` **appends** (`_persist_decision`/`_persist_candidate_meta`/`history.append_event`). resume reads files only (`load_or_init_state`, `runner.py:1864`) — no git needed.
- `commit_iteration` (`runner.py:1826`) stops staging metadata. It still calls `_persist_candidate_meta`/`_persist_decision` (they write the durable files), then commits **only** `config.allowed_path`, and **only** for code-advancing statuses (`keep`, `success`, `lineage_advance`, `reset`). `reject`/`repair_rollback`/`abort` become no-ops (nothing to commit — the tree is clean because `runs/` is ignored and the workspace was already rolled back).
- **F2 abort-commit is now obsolete.** Its sole purpose (per the `runner.py:2352-2357` comment) was so the next job's `ensure_worktree_ready` wouldn't see `runs/_summary/<job>_state.json` as a *modified tracked file* and refuse to start. Once `runs/` is ignored, the state file is **never a tracked file**, so a dirty state file can never trip `ensure_worktree_ready` (which checks `disallowed_candidate_paths` + workspace-dirty, both reading plain `git status` that is blind to ignored `runs/`). The four `commit_iteration(..., "abort", ...)` calls in `run_job` (`runner.py:2316/2336/2359/2373`) become guaranteed no-ops (status not in the code-advancing set) — we remove them and rewrite `test_run_job_commits_aborted_state_when_commit_results`.

### D4 — Interaction with the Phase 1 lineage-set (`--set-budget>1`)

The set path (already implemented, `runner.py:2214-2280`) calls `commit_iteration` with `lineage_advance` / `keep` / `success` / `reject` and, on `promote`, reads `git rev-parse HEAD` then `gitops.advance_champion_ref(repo, ref, HEAD)`.
- **Code-only commits still give a real HEAD for champion advance.** `lineage_advance` / `keep` / `success` are in the code-advancing set, so they commit `workspace/transcribe.py` → HEAD moves to a real commit containing the promoted code → `advance_champion_ref(HEAD)` is correct. (If the promoted code is byte-identical to the prior lineage commit, `commit_iteration` skips — `git diff --cached --quiet` returns 0 — and `rev-parse HEAD` returns the existing lineage commit, which still contains the code; champion advance is still correct.)
- **Metadata-only iters (reject = repair) simply don't commit.** With code-only staging, a `reject`/`repair_rollback` stages nothing (workspace already rolled back to lineage/champion → no diff) and commits nothing; the tree stays clean because `runs/` is ignored. This **eliminates the Phase-1 "accepted churn"** (Phase 1 plan Task 8 caveat: the reset-restore previously produced a noisy revert commit).
  - **Subtlety to cover in tests:** on `reset`, `restore_file_from_ref(champion)` may leave `workspace/transcribe.py` *differing from the job-branch HEAD* (which is the lineage head, not champion). That is an **untracked-content difference on a tracked file** → it shows as ` M workspace/transcribe.py`, a *tracked-modified* path. The next iter's `ensure_worktree_ready` would reject it as "workspace dirty before candidate generation". **Therefore reset must still commit the champion-restore as a code checkpoint** so HEAD == champion code and the tree is clean. Decision: keep a commit on `reset` *only* — i.e. treat `reset` as a code-advancing checkpoint (`reset` joins `_CODE_CHECKPOINT_STATUSES`; `repair` does not). This is correct and minimal: `reset` genuinely changes the on-disk code (back to champion), so it *is* a code checkpoint; `repair` rolls back to the lineage head == current HEAD, so its tree is already clean and no commit is needed. The set path therefore commits `reset` with status `"reset"` and `repair` with status `"repair_rollback"` (no-commit), while the `IterationResult.status` stays `"reject"` for `run_job`'s accounting (Task 4 Step 6).

### D5 — `_init_repo` and the scope-violation tests updated to the new guard

`_init_repo` (`tests/test_harness_runner.py:58`) writes `.gitignore` = `runs/*\n!runs/_summary/\n` and `git add`s `runs/_summary/HISTORY.md`. Update the `.gitignore` to `runs/\n` (match production) and **drop** `runs/_summary/HISTORY.md` from the initial `git add` (it is now ignored; `git add` of an ignored path errors). The two scope-violation tests (`test_run_iteration_rejects_and_rolls_back_summary_scope_violation`, `test_run_iteration_rejects_when_candidate_writes_summary_during_verify`) keep their *assertions* (poison removed, original restored, reject narrative appended) — they pass against the new guard because the snapshot diff sees the `runs/_summary/HISTORY.md` poison (now ignored) and the tracked `baseline/` poison is still caught by `git status`. `test_step1_decision_trace_committed_and_survives_next_iter` converts its `_tracked(...)` asserts to on-disk-existence asserts (the trace is durable-but-untracked).

```python
def candidate_owned_statuses(
    statuses: list[GitPathStatus], config: RunnerConfig
) -> list[GitPathStatus]:
    """Paths on the *tracked* surface the candidate is responsible for and that
    rollback may revert. PRECISE (phase1.5): exactly the candidate's own surface —
      - config.allowed_path (workspace/transcribe.py),
      - anything under runs/<hyp_id>/ (its own verify output, if it ever surfaces
        as a tracked/untracked status — it does not once runs/ is ignored, but the
        clause is harmless and keeps the pre-gitignore-flip iterations correct).
    Crucially this NO LONGER returns arbitrary non-runs/ untracked paths: a stray
    untracked file the candidate never created must never be deleted by rollback
    (the real-world git-clean collateral-damage hazard). A candidate write to a
    NEW tracked path outside this set (e.g. docs/foo) is a scope VIOLATION —
    detected by disallowed_*_paths and rejected — and removed precisely by feeding
    the disallowed/post_violations list to rollback_paths (Task 3); it is never
    'owned' here, so an unrelated file is never swept up. Poison under the now-
    ignored runs/_summary/ surface is detected/removed separately by the snapshot
    diff (Task 2)."""
    owned: list[GitPathStatus] = []
    for status in statuses:
        parts = status.path.parts
        if status.path == config.allowed_path:
            owned.append(status)
        elif parts[:1] == ("runs",):
            # runs/<hyp_id>/... (or runs/_summary/... pre-flip) — the candidate's
            # own per-iter output dir.
            owned.append(status)
    return owned
```

> **Design note (why this is still safe):** the previous third clause `parts[:1] != ("runs",)` existed to *clean up candidate writes to new top-level paths* (e.g. the candidate creates `docs/foo`). Those are caught as **scope violations** by `disallowed_*_paths` (which reject the iter) — but with the old clause they were also *deleted* as "owned", which is what swept up the unrelated stray file. The precise version owns only the candidate's legitimate tracked surfaces. A candidate write to a *new* tracked path outside those is still **detected and the iter rejected**; to remove that specific poison without re-introducing the collateral hazard, the scope-violation reject path removes exactly the detected violation paths (Task 3). The now-ignored `runs/_summary/` poison is handled by the snapshot diff (Task 2). Neither path touches an unrelated stray file.

```python
def rollback_paths(repo_root: Path, statuses: list[GitPathStatus]) -> None:
    """Revert exactly the given tracked-surface paths. Tracked-modified →
    git restore (back to HEAD). Untracked (`??`) → precise filesystem delete
    (os.remove / rmtree) of ONLY the listed paths — never `git clean`, which
    (a) won't remove ignored files and (b) caused the real-world collateral
    deletion of an unrelated untracked file (phase1.5). Callers pass
    candidate_owned_statuses(...) or the precise scope-violation list, so nothing
    outside the candidate's writes is ever passed here. (Ignored-surface poison is
    handled by remove_ignored_poison, not this function.)"""
    if not statuses:
        return
    tracked = [str(s.path) for s in statuses if not s.untracked]
    removable = [s for s in statuses if s.untracked]
    if tracked:
        _run_git(repo_root, ["restore", "--", *tracked])
    for s in removable:
        target = repo_root / s.path
        if target.is_dir() and not target.is_symlink():
            shutil.rmtree(target, ignore_errors=True)
        elif target.exists() or target.is_symlink():
            try:
                target.unlink()
            except FileNotFoundError:
                pass
```

```python
def snapshot_ignored_surface(repo_root: Path) -> dict[str, Any]:
    """Cheap snapshot of the IGNORED surface a candidate could poison: every file
    under runs/_summary/ (as {relpath: (mtime_ns, size)}) plus the set of existing
    top-level runs/<dir> names. This is O(metadata) — runs/_summary/ holds ~5
    files/job — NOT an O(repo) walk, and it deliberately ignores runs/_archive/
    and prior runs/<hyp>/ contents (the ~2584-file class): those dirs are listed
    only by name at the top level, and a name present in both snapshots is never a
    diff. Used to detect candidate writes git can no longer see once runs/ is
    gitignored (phase1.5)."""
    summary = repo_root / "runs" / "_summary"
    files: dict[str, tuple[int, int]] = {}
    if summary.is_dir():
        for p in summary.rglob("*"):
            if p.is_file():
                st = p.stat()
                rel = p.resolve().relative_to(repo_root.resolve()).as_posix()
                files[rel] = (st.st_mtime_ns, st.st_size)
    runs = repo_root / "runs"
    top_dirs: set[str] = set()
    if runs.is_dir():
        top_dirs = {child.name for child in runs.iterdir() if child.is_dir()}
    return {"summary_files": files, "top_dirs": top_dirs}


def diff_ignored_surface(
    before: dict[str, Any], after: dict[str, Any], hyp_id: str
) -> list[Path]:
    """Return the repo-relative ignored-surface paths the candidate created or
    modified this iter: any new/changed file under runs/_summary/, plus any new
    top-level runs/<dir> that is NOT the current runs/<hyp_id>/. Pre-existing
    files/dirs (identical in both snapshots) are never returned, so the ~2584
    pre-existing ignored files never false-reject (phase1.5)."""
    flagged: list[Path] = []
    before_files: dict[str, tuple[int, int]] = before["summary_files"]
    after_files: dict[str, tuple[int, int]] = after["summary_files"]
    for rel, meta in after_files.items():
        if before_files.get(rel) != meta:        # new or (mtime/size) changed
            flagged.append(Path(rel))
    new_dirs = after["top_dirs"] - before["top_dirs"]
    for name in sorted(new_dirs):
        if name == hyp_id:                        # the candidate's own dir — allowed
            continue
        flagged.append(Path("runs") / name)
    return flagged


def remove_ignored_poison(repo_root: Path, paths: list[Path]) -> None:
    """Precise filesystem delete of exactly the diff-flagged ignored poison paths
    (os.remove / rmtree) — never git clean. Collateral-free: only the listed paths
    are removed (phase1.5)."""
    for rel in paths:
        target = repo_root / rel
        if target.is_dir() and not target.is_symlink():
            shutil.rmtree(target, ignore_errors=True)
        elif target.exists() or target.is_symlink():
            try:
                target.unlink()
            except FileNotFoundError:
                pass
```

Replace `commit_iteration` (`runner.py:1826-1861`):

```python
# Statuses that advance the on-disk code and therefore checkpoint the workspace
# as a git commit. keep/success = promotion; lineage_advance = in-set lineage
# head; reset = workspace restored to champion (a real code change, must be a
# checkpoint so the next ensure_worktree_ready sees a clean tree == HEAD).
# reject/repair_rollback/abort do NOT advance code (workspace already == HEAD
# after rollback) → no commit. (phase1.5, HARNESS-REDESIGN §80.)
_CODE_CHECKPOINT_STATUSES = ("keep", "success", "lineage_advance", "reset")


def commit_iteration(
    config: RunnerConfig,
    state_path: Path,
    status: str,
    hyp_id: str,
    iteration: int,
    reason: str | None = None,
    attempt_status: str | None = None,
) -> None:
    # Metadata is written to disk (append-only / atomic) but NOT committed — it
    # lives under runs/, now fully gitignored. Persist first (these write the
    # durable files), then commit ONLY the code file for code-advancing statuses.
    _persist_candidate_meta(config, hyp_id, iteration, status)
    _persist_decision(
        config, hyp_id, iteration, status, reason=reason, attempt_status=attempt_status
    )
    if status not in _CODE_CHECKPOINT_STATUSES:
        return
    _run_git(config.repo_root, ["add", "--", config.allowed_path.as_posix()])
    diff = _run_git(config.repo_root, ["diff", "--cached", "--quiet"], check=False)
    if diff.returncode == 0:
        return
    _run_git(
        config.repo_root,
        ["commit", "-m", f"iter{iteration}: {status} {hyp_id}"],
    )
```
